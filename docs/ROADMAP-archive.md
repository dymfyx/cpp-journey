## P3（旧）· MiniKV：从零实现 LSM-Tree 键值存储引擎

**做什么**
- API：`Put / Get / Delete / Scan / WriteBatch`。
- 核心组件：WAL（顺序写 + 崩溃恢复）→ MemTable（跳表）→ 冻结 MemTable → SSTable（数据块 + 索引块 + 布隆过滤器 + footer）→ 分层 Compaction → Manifest/Version 元数据 → 多路归并迭代器 → LRU Block Cache。
- 并发：后台 compaction 线程 + 前台读写；MVCC 序列号实现快照读。
- 测试：随机操作与 `std::map` 对拍；`kill -9` 崩溃恢复测试；并发正确性测试。
- 性能：顺序写 / 随机读 / 范围扫描 benchmark，`perf` 火焰图定位，与 LevelDB 对比。

**为什么做 / 有什么用**
- 数据库内核是 C++ 基础架构岗最硬的项目，LevelDB 简化版几乎是「标配」简历项目，但真正写出来的人不多。
- 覆盖的知识密度最高：数据结构（跳表、布隆过滤器、堆归并）+ 文件格式设计 + 并发 + 崩溃一致性 + 性能调优。
- 产物有实用价值：可以作为嵌入式 KV / 本地缓存 / 配置存储。

**学到什么**：模板与泛型、内存池/LRU、二进制序列化与文件格式、并发控制与崩溃恢复、模型对拍测试、设计文档写作。

**里程碑（14 周）**
- W1–2 接口 + WAL + MemTable → W3–4 SSTable 读写 → W5–6 迭代器 + 布隆过滤器
- W7–9 Compaction + Version/Manifest → W10–11 崩溃恢复 + MVCC
- W12–13 性能调优 + 与 LevelDB 对比 → W14 设计文档 + 复盘

**验收 / 简历亮点**
- [ ] 跑通 DB-Bench 风格 benchmark，有随机写/顺序写/随机读/扫描数据
- [ ] 崩溃恢复：随机 kill -9 100 次，数据无丢失、无损坏
- [ ] 与 std::map 对拍 100 万次随机操作结果一致
- [ ] `docs/design.md` 讲清存储格式与 compaction 策略
- [ ] 简历句：「从零实现 LSM-Tree 存储引擎，含 WAL、跳表 MemTable、SSTable、布隆过滤、分层 Compaction 与 MVCC；随机写 XX kops/s，崩溃恢复经 100 次 kill -9 验证；对比 LevelDB 分析读写放大。」

**难度 ★★★★ ｜ 参考**：LevelDB/RocksDB 设计文档、DDIA 第 3 章、Mini-LSM（skyzh）教程。

## P4（旧）· RayTracer：CPU 路径追踪渲染器

**做什么**
- 数学基础：`vec3`、`ray`、相机（含景深）。
- 场景：球体/平面/三角网格 + BVH 加速（SAH 构建）。
- 材质：Lambertian 漫反射、Metal、Dielectric（玻璃折射）；路径追踪 + 俄罗斯轮盘 + 抗锯齿多重采样。
- 工程：多线程分块渲染、渐进式显示、OBJ 加载、PNG 输出、场景用 JSON 配置（复用 P1 的 jqlite）。

**为什么做 / 有什么用**
- 图形/游戏/引擎/仿真方向的核心敲门砖；README 放渲染图，视觉冲击力在所有项目里最强。
- 是「数学 + 泛型 + 多态 + 性能优化 + 第三方库集成」的综合练习，而且没有标准答案，能体现审美和取舍。
- 和「计算机图形学」课程同步，课程作业可以直接升级成项目。

**学到什么**：泛型与运算符重载、多态或 variant 的场景抽象、BVH 构建与遍历、性能优化（数据布局/缓存/SIMD/多线程）、第三方库集成（stb_image、tinyobjloader）。

**里程碑（12 周）**
- W1 vec3 + 相机 + 球体 → W2 材质 + 光照 → W3 BVH → W4 路径追踪
- W5 多线程 → W6 OBJ/场景 JSON → W7–8 优化 + 分辨率/采样实验
- W9–10 文档 + 渲染图 + 博客 → W11–12 扩展（纹理/体积雾/GPU 版任选）

**验收 / 简历亮点**
- [ ] 1080p、256 spp 场景有渲染时间数据（8 线程 ≤ 60 s 为目标）
- [ ] BVH 相对暴力遍历有加速比数据（通常 10×+）
- [ ] README 放 3–5 张渲染图 + 场景配置
- [ ] 简历句：「实现 CPU 路径追踪渲染器，BVH + SAH 加速、多线程分块渲染；1080p 256spp 场景 XX 秒，BVH 带来 XX× 加速；支持 OBJ 与 JSON 场景配置。」

**难度 ★★★ ｜ 参考**：《Ray Tracing in One Weekend》三部曲、tinyrenderer（ssloy）。

## P5（旧）· MiniLang：解释器 + 字节码虚拟机

**做什么**
- 第一遍（tree-walk）：词法 → 递归下降语法树 → 作用域解析 → AST 解释器；支持变量、控制流、函数、闭包、类与继承。
- 第二遍（bytecode VM）：单遍编译器 → 栈式虚拟机 → 常量表 → 标记-清除 GC → REPL。
- 工程：行列号错误信息、黄金测试套件、标准库（字符串/数组/哈希/时间）。

**为什么做 / 有什么用**
- 编译器/语言/工具链/AI infra 方向的硬通货；也是把「算法 + 数据结构 + 系统设计」串起来的最好练习。
- 面试里能讲 30 分钟：闭包怎么实现、GC 怎么标记、VM 指令怎么设计。
- 产物实用：可以给自己写脚本、写 DSL、做配置语言。

**学到什么**：AST 节点的所有权与 GC、visitor/variant 两种遍历风格、哈希表/栈帧/调用约定/指令编码、回归测试工程。

**里程碑（14 周）**
- W1 lexer → W2 parser → W3–4 AST 解释器 → W5 闭包 → W6 类与继承
- W7–8 单遍编译器 → W9–10 栈 VM → W11–12 GC
- W13 标准库 + 错误信息 → W14 文档 + 教程 + 复盘

**验收 / 简历亮点**
- [ ] 通过 Crafting Interpreters 官方测试套件 90%+
- [ ] 能跑经典程序（斐波那契、闭包计数器、类继承例子、排序）
- [ ] 有 GC 日志/统计，能解释内存回收过程
- [ ] README + 一篇「从零实现一门语言」教程
- [ ] 简历句：「从零实现脚本语言 MiniLang，含递归下降解析、闭包、类继承、字节码 VM 与标记清除 GC；通过 XXX 个测试用例。」

**难度 ★★★★ ｜ 参考**：Crafting Interpreters（免费在线，强烈推荐）。

## P6（旧）· RaftKV：基于 Raft 的分布式键值存储

**做什么**
- Raft：leader 选举、日志复制、持久化、快照、成员变更（可选）。
- 服务层：KV API、线性一致读（读索引/租约）、客户端请求去重。
- RPC：自研或 gRPC。
- 测试：网络模拟（延迟/丢包/分区）、随机崩溃注入、线性一致性检查（Jepsen 风格）。

**为什么做 / 有什么用**
- 分布式系统是后端/基础架构的顶级加分项，MIT 6.824 级别的项目能明显区分候选人。
- 面试可以聊：脑裂怎么防、日志怎么追上、快照怎么传、线性一致怎么保证。

**学到什么**：共识/复制/容错/一致性模型、多线程 Raft 与锁粒度、故障注入与确定性测试、可观测性。

**里程碑（14 周）**
- W1–2 RPC + 单机 KV → W3–5 leader 选举 → W6–8 日志复制
- W9–10 持久化 + 快照 → W11–12 KV 线性一致读
- W13–14 故障注入测试 + 文档

**验收 / 简历亮点**
- [ ] 3/5 节点集群在随机 kill/网络分区下数据不丢、不乱
- [ ] 线性一致性检查通过
- [ ] 文档讲清 Raft 实现与测试方法
- [ ] 简历句：「基于 Raft 实现 3 节点分布式 KV，支持日志复制、快照与线性一致读；在网络分区与随机崩溃注入测试下保持一致性。」

**难度 ★★★★★ ｜ 参考**：MIT 6.824、Raft 论文、etcd/raft 实现。
